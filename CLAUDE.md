# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

Personal dotfiles for NixOS (i3) and macOS (AeroSpace), on a single `main` branch. The repo is checked out to `~/dotfiles`. On NixOS a flake declares the whole system for two hosts (`laptop`, `desktop`), and home-manager symlinks individual configs into `~/.config` and `~/`. On macOS `install.sh` creates the same kind of symlinks. There is no test or lint pipeline — dotfile changes take effect by editing files in place (the live configs are symlinks back into this repo).

## Layout / what each top-level dir is

Shared config dirs symlinked to `~/.config/<name>`: `alacritty`, `fish`, `nvim`, `kanata`. Linux-only: `i3`, `polybar`, `picom`, `ranger`, `rofi`, `feh`, `autorandr` (per-machine monitor profiles, matched by EDID), plus `code-flags.conf` and `.xinitrc`. macOS-only: `aerospace`, `.aerospace.toml`. Shared loose files: `starship.toml`, `.tmux.conf`, `.prettierrc`. `git/config`, `git/ignore` and `git/allowed_signers` (public signing keys, one line per machine) link into `~/.config/git/`; machine-specific git settings (credential helper, `safe.directory`) go in the untracked `~/.config/git/local`, which `git/config` includes.

Agent tooling configs are organized to be shared across CLIs:

- `.claude/` → symlinked piecewise into `~/.claude/` (subdirs: `agents/`, `skills/`, `rules/`, `output-styles/`, `hooks/`). MCP servers live in `~/.claude.json` and are NOT in this repo. `settings.json` is tracked but marked assume-unchanged locally (Claude Code rewrites it); `settings.local.json` is gitignored. `plugins/` is app-managed and not tracked.
- `.codex/` → symlinked piecewise into `~/.codex/` (subdirs: `agents/`, `hooks/`, `rules/`, plus `AGENTS.md` and `hooks.json`). Main config (`config.toml` and MCP) lives outside this repo.
- `.agents/skills/` → symlinked to `~/.agents/skills/`, the cross-tool Agent Skills location consumed by Codex.

The `.claude/` tree keeps Claude's native structure. The `.codex/` tree keeps Codex-specific equivalents: global instructions in `AGENTS.md`, hook wiring in `hooks.json`, shell scripts under `hooks/`, command rules under `rules/`, and optional custom agents under `agents/`.

## NixOS

- `flake.nix` builds `nixosConfigurations.<host>` from `nixos/hosts/<host>/` plus home-manager (`nixos/home/`).
- `nixos/modules/`: shared system config. `system.nix` covers boot, nix, networking, users, sshd, sudo and the ssh-agent; `desktop.nix` covers X/i3, audio, Firefox prefs, fonts and autorandr; `packages.nix` is the package list.
- `nixos/hosts/<host>/default.nix`: machine-specific config (desktop: NVIDIA `legacy_580` for its Pascal GPU, VA-API, out-of-tree `rtl8821ce` Wi-Fi driver in `rtl8821ce.nix`, `/data` mount; laptop: Intel VA-API, brightness, thermald). `hardware-configuration.nix` is generated by `nixos-generate-config`.
- `nixos/home/default.nix` parses `links.Linux` and turns each two-column entry into an out-of-store symlink, so `links.Linux` stays the single list of links. It also sets the GTK theme and the kanata user service.

Apply changes:

```
sudo nixos-rebuild switch --flake ~/dotfiles#<host>   # laptop | desktop
nix flake update                                       # bump nixpkgs/home-manager, then rebuild
```

Flakes only see git-tracked files: `git add` new files before rebuilding. Editing an already-linked file applies immediately; adding a new `links.Linux` entry needs a rebuild. Keep secrets (Wi-Fi passwords, private keys) out of the Nix config, since the repo is public.

## macOS install

```
~/dotfiles/install.sh
```

The script is idempotent — safe to re-run on an already-installed system. `install.sh` is OS-agnostic; what gets linked is declared in `links.$(uname)` (`links.Linux`, `links.Darwin`), one `src dst` per line (`src` relative to the repo root, `~` allowed in `dst`, `#` comments). To link a new config, add a line to the relevant `links.*` file(s) — don't edit `install.sh`. For each entry it creates missing parent dirs and replaces an existing symlink via `ln -sfn`; if the destination exists and is not a symlink it prints `skip: ...` and leaves it untouched, and a missing `src` prints `missing: ...`. An optional third column `sudo` is for root-owned targets. On NixOS, don't run it; home-manager owns the links and system files belong in the NixOS modules.

Editing any file in this repo updates the live config immediately via the symlink — no reload step beyond whatever the target tool needs (e.g. `i3-msg restart`, `:source` in nvim, `exec fish`).

## Neovim config structure

Entrypoint `nvim/init.lua` loads `lua/sets.lua`, `lua/keymaps.lua`, and `lua/plugins.lua`. Plugin manager is **packer.nvim** (compiled output `nvim/plugin/packer_compiled.lua` is gitignored). Per-plugin setup lives in `nvim/lua/pluginsConf/` with `init.lua` as the dispatcher; add a new plugin by declaring it in `plugins.lua` and creating a matching `pluginsConf/<name>.lua` required from `pluginsConf/init.lua`. After changing `plugins.lua`, run `:PackerSync` inside nvim.

## Fish shell config

`fish/config.fish` is the entrypoint. `fish/conf.d/` is autoloaded (note: `conf.d` is gitignored except `nvm.fish` and `z.fish`, which are force-tracked). `fish/functions/` holds individual function files (one function per file, fish convention). Plugins (z, bass) are vendored: their files are committed directly and there is no plugin manager, so update them by copying in new upstream files. Prompt is starship (`starship.toml` at repo root).

## Per-OS differences

There are no per-OS branches. Shared configs carry small OS checks instead; prefer extending these over duplicating files:

- nvim: `vim.fn.has("mac") == 1` (NvimTree focus keymap, php-cs-fixer, pylint).
- fish: `if test (uname) = Linux` in `config.fish`.
- alacritty: `alacritty.toml` imports `~/.config/alacritty-os.toml`, which `links.*` points at `alacritty/linux.toml` or `alacritty/macos.toml`.
- kanata: `(platform (macos) ...)` / `(platform (linux) ...)` blocks; every layer must keep the same key count as `defsrc`.

## Conventions worth knowing

- `.gitignore` excludes `nvim/plugin/packer_compiled.lua`, `fish/fish_variables`, `fish/conf.d`, `.DS_Store`, `*.bak`, `.claude/settings.local.json` and `.claude/skills/synced/`. Don't try to commit generated/local state in those paths.
- On NixOS, packages go in `nixos/modules/packages.nix` (shared) or the host's `default.nix` (machine-specific).
- `checkstyle.xml` and `.prettierrc` are personal style configs used by editors/projects, unrelated to this repo's own tooling.
